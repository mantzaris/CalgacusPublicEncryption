# Stage 7 public arithmetic comparator audit

Inspected primary paper: Ziegler, Deng and Rush, **Neural Linguistic Steganography**, EMNLP-IJCNLP2019, pp1210–1215, [D19-1115](https://aclanthology.org/D19-1115/), DOI10.18653/v1/D19-1115. §§2–3 (pp1211–1212) specify shared mapping/model assumptions, the arithmetic reversal, and finite-message stopping; §4 discusses model distributions, truncation and evaluation. This paper already establishes the arithmetic probability-matching idea. Its limiting distribution account is not an unconditional finite-packet security theorem for our construction.

Inspected official source: [harvardnlp/NeuralSteganography](https://github.com/harvardnlp/NeuralSteganography/tree/14e982564aeaf9a33f7b4de440deda2184d17f12), exact commit14e982564aeaf9a33f7b4de440deda2184d17f12, `arithmetic.py` encode/decode, `utils.py`, README and requirements. The local reference checkout has that revision. No LICENSE/COPYING file is present in that tree. **No upstream source is copied or redistributed.** This project's code is an independently written adaptation of the published method. Source hashes and dependency list are retained as audit metadata. No inference or legacy environment was installed for the upstream repository.

The inspected code uses PyTorch/Transformers (requirements pin torch2.7.1, transformers4.52.4, numpy2.0.2), precision16 by default, GPT token exclusions, a probability-dependent truncated alphabet, integer mass corrections and shared-prefix renormalization. Its decoder repairs particular GPT tokenizations and treats its final token specially. Those details do not meet this study's unchanged UTF-8 contract without adaptation.

Our single implementation path changes: backend to the already frozen llama.cpp/Llama3 Q4_K_M runtime; support to the existing public canonical first16/top128 alphabet; frequencies to positive largest-remainder totals65536; precision32 with standard E1/E2/E3 finite arithmetic intervals; stopping to the first complete public-size-class stable packet, midpoint suffix and canonical integer replay; transport to strict actual UTF-8 without repair; profile binding to existing HPKE; serial cleared cache and deterministic logit/token-ID ordering. No keyed construction is relabelled public. These are engineering conventions, not inventions or an unmodified upstream replication.

F retains its actual mapping. Only its new public contexts and explicit size-class configuration receive new hashed profile identities. Existing historical profiles/codecs/records remain identifiable. Both methods directly inherit `PublicUtf8Rank16Codec.candidates`; no competing admission implementation exists.

The necessary X25519 output representation check is reused from Stage6, grounded in [RFC7748 §5](https://www.rfc-editor.org/rfc/rfc7748.html#section-5) and [RFC9180 §§4.1/7.1.1](https://www.rfc-editor.org/rfc/rfc9180.html#section-7.1.1). It tests canonical honest-sender output encoding, not curve validity, ciphertext authentication or sender identity. Public extraction needs no private key. Fixed packet representation, termination, restricted support and abort conditioning must be analyzed separately from model probability matching.
