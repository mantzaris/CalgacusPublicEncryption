# Bounded Stage 1 development evaluation

The hard cumulative ceilings are **7,200 conservative GPU-job seconds, 25,000 charged tokens, and 72 total cases**. The governor charges every model-evaluated token, including source scoring, public-context prefill, reconstruction, controls, warmups if any, failed operations, and public inversion. This upper-bounds generated-token usage. Conservative carry-in is 30 seconds and one case for the preceding GPU connectivity check (matrix operation and backend initialization; zero LLM tokens).

`run_smoke.py` reserves wall time, tokens and one case before each child launch in the one project ledger. Model loading/hashing/imports, occupied CPU processing and teardown are included in elapsed job time. A controller watchdog and independent kernel wall timer terminate a child eight seconds before its reserved wall ceiling. Linux parent-death signaling also kills a worker if its controller exits. The first three completed GPU cases predate these additional worker-side guards; no interrupted job occurred. Their original revision and accounting remain preserved. Token charges happen before evaluation. A killed/abandoned worker retains its full reservation on restart. Atomic append+fsync and an exclusive ledger lock prevent concurrent budget consumers. The ledger is never reset. GPU kernels are not used as the time denominator. Controller gaps without a live model are not charged. Sampled PID-specific VRAM is evidence, not an exact allocator maximum.

Frozen allocation: two unchanged Calgacus cell-10 function examples under the local model/runtime; twelve adapted HPKE examples (six independently generated keys, each at 32 and 128 bytes); three ordinary controls matched to the first produced carrier per context; up to three fresh receiver processes selected as the first successful encrypted carrier per public context. No retries, replacing failures, parameter sweep or full factorial. Payload bytes and three contexts are researcher-authored synthetic development data. All are permanently excluded from future held-out evaluation. Fresh HPKE ephemeral randomness and message IDs use OS randomness; ordinary sampling alone uses documented PCG64 seeds. Seeds are not keys.

An observer independently extracts three prespecified encrypted cases and the three controls, without private keys or tag checks. Counts are diagnostic; no AUROC, significance tests, fitted classifier, detector training or general concealment conclusion is warranted. Clean-process replay starts from the saved UTF-8 file and test receiver key; source equality is checked by the parent evaluator, outside the receiver.

Every reserved attempt retains immutable UUID, input, command, native runtime log, model/context trace, result and memory samples where available. First divergence compares intended/retokenized IDs, source/receiver ranks and reconstructed source IDs. Invalid UTF-8 bytes remain as hex; such a case has no valid transmitted text. Failure families: capacity exhaustion, tokenization/serialization drift, rank/numerical divergence, framing, authentication, and timeout/resource. Implementation faults are additionally explicit. Unexplained numerical/runtime failures stop GPU work for investigation; they are not discarded on continuation.

Later evaluation requires an external Stage 1 review, novelty decision and new budget. It should split source document/context families, payloads and receiver keys before tuning; register training/validation/test groups; preserve failed attempts in intention-to-send recovery and goodput; compare same-envelope public arithmetic coding and an independently keyed reference with honest setup differences; use matched-length and operational length analyses; and compare public format extraction with ordinary model controls. No such research matrix runs in this stage.

The next-stage forecast in the report derives from observed per-case wall time and operation timings with at least 25% contingency. It is conditional on resolving transport and comparator issues, not a measured full-program cost or authorization.
